01 · Background

왜 지금 context / KV compression이 중요한가?

모델은 점점 더 긴 context를 쓰지만, inference는 모든 past token을 같은 비용으로 계속 누적한다.
Models need long context

Test-time scaling / reasoning

모델이 바로 답하지 않고 긴 CoT로 계획, 분해, 검증, backtracking을 수행하면서 generated reasoning token 자체가 context로 누적된다.[1, 2, 3]

Multi-turn agent

목표를 해결하는 동안 tool call/action, observation/tool output, working memory/plan이 interaction trajectory로 쌓인다.[4, 5]

Extending context window is not enough

System cost는 token마다 누적된다

N = prompt + reasoning + trajectory. KV cache는 N에 따라 커지고, decode step마다 past KV를 다시 읽어 memory, bandwidth, latency bottleneck을 만든다.[6, 7, 8]

Long context는 reliable memory가 아니다

Window를 키워도 lost-in-the-middle, forgetting, irrelevant history distraction, overthinking redundancy가 남는다. 그래서 context / KV compression이 필요해진다.[4, 9, 10, 11]

그래서 context / KV compression은 reasoning model과 agent를 서빙하기 위해 꼭 필요한 중요한 문제다.

02 · Background

Transformer의 residual stream 위에서 동작하는 attention 메커니즘

attention head 의 QK · OV circuit decomposition[1]
▸ Q와 K로 "어디를 읽을지" 결정 — 현재 token의 query를 모든 과거 token의 key와 내적해 유사도 계산 → softmax로 각 위치의 읽기 가중치 분포
▸ 그 가중치로 V를 가중합 (soft read) — 과거 token의 value를 가중합해 현재 token의 residual stream에 더해짐 → 메모리에서 "soft하게" 값을 읽어오는 연산
▸ K, V는 step마다 누적되는 read-only cache — autoregressive 생성에서 매 step 1..t의 K, V 전부를 다시 읽음 → 시퀀스 길이 N에 비례한 메모리·bandwidth → KV / context compression
Algorithm — Self-Attention $(\mathbf{X} \,\|\, \boldsymbol{\mathcal{W}}_{qkv}, \text{Mask})$[2,3]
Input. $\mathbf{X} \in \mathbb{R}^{d_{\mathrm{x}} \times \ell_{\mathrm{x}}}$
Output. $\mathbf{H} \in \mathbb{R}^{d_{\mathrm{out}} \times \ell_{\mathrm{x}}}$
Params. $\boldsymbol{\mathcal{W}}_{qkv} = \{\mathbf{W}_q, \mathbf{b}_q;\ \mathbf{W}_k, \mathbf{b}_k;\ \mathbf{W}_v, \mathbf{b}_v\}$
Mask. $\in \{0,1\}^{\ell_{\mathrm{x}} \times \ell_{\mathrm{x}}}$  (causal for autoregressive LM)
1$\mathbf{Q} \leftarrow \mathbf{W}_q \mathbf{X} + \mathbf{b}_q \mathbf{1}^\top$
2$\mathbf{K} \leftarrow \mathbf{W}_k \mathbf{X} + \mathbf{b}_k \mathbf{1}^\top$
3$\mathbf{V} \leftarrow \mathbf{W}_v \mathbf{X} + \mathbf{b}_v \mathbf{1}^\top$
4$\mathbf{S} \leftarrow \mathbf{K}^\top \mathbf{Q}$
5$\forall t, t':\ \text{if } \neg\text{Mask}[t, t']\text{ then } \mathbf{S}[t, t'] \leftarrow -\infty$
6$\textbf{return}\ \ \mathbf{H} = \mathbf{V} \cdot \mathrm{softmax}\!\left(\dfrac{\mathbf{S}}{\sqrt{d_{\mathrm{attn}}}}\right)$
[1] Elhage, N. et al. A Mathematical Framework for Transformer Circuits. Anthropic, 2021. transformer-circuits.pub/2021/framework/index.html.
[2] Phuong, M. & Hutter, M. Formal Algorithms for Transformers. arXiv:2207.09238, 2022. (Algorithm 4)
[3] 원 알고리즘은 cross-attention까지 일반화된 $(X, Z)$ 형태이나, 본 발표 대상인 디코더-only LLM(GPT 류)은 self-attention이므로 $Z\!=\!X$로 두어 단일 시퀀스 $X$에 대한 형태로 단순화함.
03 · Literature Review

선행 연구는 어디를 줄였고, 어떤 아이디어로 접근했나?

KV cost : $\mathbf{o}_t \,=\, \mathrm{softmax}\!\left(\dfrac{\mathbf{Q}_t \, \mathbf{K}^\top}{\sqrt{d_{\mathrm{attn}}}}\right)\mathbf{V}, \;\; \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times d}, \;\; \text{cache memory} \;\approx\; L \times H \times N \times d \times \text{bit}$
A scalar bit를 줄인다 mem ↓lat ↓
일부 KV cache를 low-bit로 줄인다. (KIVI, ICML'24; KVQuant, NeurIPS'24; MixKVQ, arXiv'25)
KV를 압축하기 쉬운 표현으로 변환해 저장한다. (KVTC, ICLR'26; TurboQuant, ICLR'26)
B dimension d를 줄인다 mem ↓lat ↓
Low-rank latent vector로 저장한다. (MLA, arXiv'24; Palu, ICLR'25; Eigen, EMNLP'24; TransMLA, NeurIPS'25; MLRA, ICLR'26; A3, ICML'26; KQ-SVD, AISTATS'26)
덜 중요한 dimension을 제거한다. (ThinK, ICLR'25)
C KV 수 N을 줄인다 mem ↓lat ↓
과거 attention score가 높았던 token을 남긴다. (H2O, NeurIPS'23; StreamingLLM, ICLR'24; SnapKV, NeurIPS'24)
복원/대표성 score로 남길 KV를 고른다. (KVzip, NeurIPS'25 Oral; CurDKV, NeurIPS'25)
Chunk/구조 단위로 KV를 선택/제거한다. (ChunkKV, NeurIPS'25; R-KV, NeurIPS'25; ThinKV, ICLR'26 Oral)
Layer/head/task마다 KV budget을 다르게 배분한다. (LAVa, Findings'25; EvolKV, Findings'25; DynamicKV, Findings'25)
D 중복 KV를 공유한다 mem ↓lat ↓
여러 query head가 적은 KV head를 공유한다. (MQA, arXiv'19; GQA, EMNLP'23)
여러 layer가 KV를 재사용한다. (CLA, NeurIPS'24; MiniCache, NeurIPS'24)
Head/layer 역할에 따라 KV를 공유하고, 일부 head는 제외한다. (DuoAttention, ICLR'25; RazorAttention, ICLR'25; HeadKV, ICLR'25; RLKV, ICML'26)
E 저장은 하되 step마다 덜 읽는다 lat ↓
고정 sparse pattern만 읽는다. (Longformer, arXiv'20; BigBird, NeurIPS'20)
현재 query로 읽을 page/top-k/index를 고른다. (Quest, ICML'24; SparQ, ICML'24; LoKi, NeurIPS'24; LRQK, NeurIPS'25; MInference, NeurIPS'24; SALS, NeurIPS'25)
K를 retrieval datastore처럼 쓴다. (RetrievalAttention, NeurIPS'24 W; ShadowKV, ICML'25)
F Cache 전에 context를 다시 쓴다 mem ↓lat ↓
정보가 적은 자연어 token을 줄인다. (LLMLingua, EMNLP'23; LongLLMLingua, arXiv'23)
지난 context를 요약/메모/가이드라인 자연어로 바꾼다. (MEMENTO, arXiv'26; InftyThink, ICLR'26; InftyThink+, arXiv'26; Accordion, ICML'26; MEM1, ICLR'26; MemAgent, arXiv'25; ACON, ICML'26; ConMax, arXiv'26)
자연어 대신 학습된 soft/latent token으로 context를 압축한다. (GIST, NeurIPS'23; ICAE, ICLR'24; AutoCompressor, EMNLP'23; SLT, arXiv'26)
G KV cache 밖으로 past를 보낸다 mem ⇊lat ↓
긴 문서/세션을 작은 learned KV block으로 만들어, 매번 prompt에 다시 넣지 않는다. (Cartridges, ICLR'26; Learned Structure, arXiv'25; Fast KV Compaction, ICML'26)
FFN weight를 업데이트해 맥락/사실 정보를 parameter에 반영한다. (ROME, NeurIPS'22; MEMIT, ICLR'23)
04 · Limitation of Related Work

각 접근의 한계점 — 선행 연구의 비판을 중심으로

A scalar bit
KV 하나는 작아지지만, 긴 context에서 계속 늘어나는 token 수와 매 step 읽는 양은 그대로 남는다. 지적 근거: KIVI, Quest, Cartridges
낮은 bit는 layer, head, token 분포에 민감해서 똑같이 낮추면 attention 품질이 쉽게 흔들린다. 지적 근거: KIVI, KVQuant, TurboQuant
B dimension d
Dimension을 줄여도 불필요한 과거 token은 모두 남기 때문에, 에이전트의 긴 기록 자체를 정리하지 못한다. 지적 근거: MEM1, ACON
평균 복원 오차가 낮아도, 드문 근거나 중요한 추론 단계가 작은 공간으로 압축되는 과정에서 사라질 수 있다. 지적 근거: A3, KQ-SVD, ThinKV
C KV 수 N
Token 단위로 자르면 chunk, thought, tool result처럼 함께 보존돼야 하는 묶음이 깨진다. 지적 근거: ChunkKV, ThinKV
한 번 버린 KV는 나중에 필요해도 복구하기 어렵기 때문에, 이후 질문과 긴 추론 과정에 약하다. 지적 근거: KVzip, Expected Attention, RefreshKV
D H/L sharing
Head/layer sharing은 보통 모델 구조나 학습 단계의 선택이라, 이미 학습된 기존 모델에 바로 붙이기 어렵다. 지적 근거: GQA, CLA, TransMLA
모든 head를 같이 줄이면 검색이나 추론에 중요한 head까지 같이 손상될 수 있다. 지적 근거: DuoAttention, RazorAttention, HeadKV
E read path
Step마다 덜 읽어도 full KV를 계속 저장한다면, 메모리 상한 자체는 해결되지 않는다. 지적 근거: SparQ, RefreshKV
현재 query로 고른 top-k나 index가 틀리면, 드물지만 꼭 필요한 근거를 아예 읽지 못한다. 지적 근거: Quest, LRQK, RetrievalAttention
F context rewrite
자연어 요약이나 filtering은 숫자, 코드, 인용문, 의존 관계처럼 정확히 보존해야 하는 정보를 지울 수 있다. 지적 근거: MEMENTO, Fast KV Compaction, LongLLMLingua
새 memory를 쓰는 과정에서 내용 왜곡, 상태 drift, 압축기 지연이 생길 수 있다. 지적 근거: ACON, ConMax, Fast KV Compaction
G outside cache
학습된 KV block은 보통 사전 최적화가 필요해서, 계속 변하는 에이전트 세션을 즉시 갱신하기 어렵다. 지적 근거: Cartridges, Fast KV Compaction
학습된 KV memory는 사람이 읽고 고치거나, 어떤 근거가 남았는지 확인하기 어렵다. 지적 근거: MEMENTO, Cartridges, Fast KV Compaction
각 항목은 여러 논문이 반복해서 문제로 삼은 한계점 위주로 정리했다. 지적 근거는 그 한계를 전제로 다른 compression 방향을 제안한 대표 논문이며, 정확한 언급은 Appendix A-B, Appendix C-D, Appendix E-G에 정리했다.
05 · Related Work (Specified)

자연어 기반 compression은 무엇을 다시 쓰고, 무엇을 보존하려 하나?

기존 방법은 지난 context를 자연어로 다시 쓴다. 하지만 rewrite의 기준이 prompt/rubric/reward에 의존하고, (1) 무엇을 보존해야 하는지와 (2) 어떤 자연어 표현이 효율적인지를 공통 기준으로 직접 최적화하지 않는다.

Preservation is under-specified.

  • 필수 정보의 보존 기준은 task에 맞춘 prompt/rubric/reward에 의존한다.
  • 보존 정도를 독립 metric으로 직접 측정하지 않는 경우가 많다.

Expression is under-explored.

  • 같은 정보도 여러 자연어 표현으로 쓸 수 있다.
  • 어떤 자연어 표현으로 rewrite해야 compression 이후 inference에 더 유리한지는 거의 다뤄지지 않았다.
Approach
무엇을 다시 쓰나
무엇을 남기나
어떤 아이디어로 줄이나
MEMENTO / InftyThink / Accordion
긴 풀이 과정을 구간 단위로 다시 쓴다.
  • 완료된 reasoning block (MEMENTO)
  • 짧은 segment로 나눈 풀이 기록 (InftyThink)
  • verbose CoT step (Accordion)
다음 풀이가 이어질 최소 상태를 남긴다.
  • 문제 상태, 변수, 제약, 중간 결론 (MEMENTO)
  • 진행 상황과 남은 하위 문제 (InftyThink)
  • 각 step의 핵심 논리 (Accordion)
다음 풀이가 끊기지 않으면 충분히 보존됐다고 본다.
  • [SFT]block마다 문제 상태를 짧은 자연어 상태로 압축한다 (MEMENTO)
  • [SFT]segment마다 progress summary를 쓰도록 학습한다 (InftyThink)
  • [RL]summary만 보고 다음 step이 이어지게 학습한다 (Accordion)
InftyThink+ / ConMax
긴 reasoning trace를 압축 대상으로 둔다.
  • 긴 풀이 과정과 요약 시점 (InftyThink+)
  • 압축된 CoT reasoning trace (ConMax)
압축 후에도 같은 답을 낼 근거를 남긴다.
  • 다음 iteration에 필요한 summary와 중간 근거 (InftyThink+)
  • 정답 예측 가능성과 reasoning coherence가 유지되는 요약된 trace (ConMax)
reward와 confidence를 proxy로 쓴다.
  • [RL]요약/계속/종료 시점을 trajectory reward로 학습한다 (InftyThink+)
  • [RL]compressed trace로도 답 confidence가 높게 한다 (ConMax)
  • [RL]reasoning coherence confidence도 reward에 넣는다 (ConMax)
MEM1 / MemAgent
지나간 기록을 고정 길이 memory로 다시 쓴다.
  • 여러 번의 대화/행동 기록 (MEM1)
  • 긴 문서를 조각별로 읽은 기록 (MemAgent)
다음 질의나 행동에 필요한 memory를 남긴다.
  • 현재 목표 상태와 이전 답변의 핵심 (MEM1)
  • 다음 행동에 필요한 사실 (MEM1)
  • 최종 QA에 필요한 answer-critical facts (MemAgent)
고정 길이 memory를 task reward로 갱신한다.
  • [RL]memory와 observation을 다음 행동용 state로 갱신한다 (MEM1)
  • [RL]chunk별 memory update를 최종 QA reward로 학습한다 (MemAgent)
ACON
agent context 중 실패를 만든 부분을 다시 쓴다.
  • 에이전트가 수행한 행동 기록.
  • 환경이나 tool이 돌려준 관찰 결과.
압축하면 실패하는 구체 정보를 남긴다.
  • 변수명, ID, 데이터 구조(schema).
  • tool output, 제약 조건.
  • 빼면 실패로 이어지는 구체 정보.
compressed context 실패로 instruction 규칙을 고친다.
  • [Prompt]full context 성공과 compressed 실패를 비교한다.
  • [Prompt]실패 원인을 압축 guideline에 반영한다.
SFT를 활용하는 방법론 계열의 공통 한계: 무엇을 좋은 rewrite로 볼지의 기준을 먼저 사람이 prompt/rubric으로 설계해야 한다.
RL을 활용하는 방법론 계열의 공통 한계: 대부분 rewritten context의 필수 정보 보존을 직접 채점하지 않고, 최종 정답/성공 또는 confidence를 proxy로 쓴다.
06 · Research Gap / Hypothesis

Context rewriting은 무엇을 최적화해야 하나?

Axis 1 · Target

What should be preserved?

사람이 사전에 정의한 prompt/rubric이나 일부 task에서만 쓸 수 있는 reward가 아니라, context 자체를 보고 반드시 남아야 하는 정보를 판단할 수 있을까?

Raw Idea
Information extraction, semantic parsing, factuality evaluation처럼 널리 쓰이는 NLP 방법론을 이용해 context 안의 사실, 상태, 의존 관계를 보존 단위로 뽑을 수 있을까?
context 자체만으로 어떤 내용이 더 중요하게 보존되어야 하는지를 점수화할 수 있을까?
Axis 2 · Metric

How do we measure preservation?

선행 연구는 final reward, confidence, failure contrast 같은 결과 기반 간접 신호를 사용한다. 이런 간접 신호 대신 필요한 정보를 얼마나 보존했는지를 독립 metric으로 직접 측정할 수 있을까?

Raw Idea
보존 단위별 중요도 점수와 rewrite 후 보존 여부를 이용해, original context와 rewrite 사이의 정보 손실량을 정량화할 수 있을까?
Axis 3 · Expression

How should it be expressed?

같은 정보도 여러 자연어 표현으로 쓸 수 있다. 어떤 기준으로 다시 써야 compression 이후 inference에 더 유리할까?

Raw Idea
같은 정보를 담더라도, inference 때 적용할 bit/dimension/read compression이 더 잘 작동하는 자연어 표현이 있을까?
요약 작성 모델을 단순히 짧게 쓰도록 학습하는 것이 아니라, compression 이후 memory/latency가 줄어드는 표현을 선호하도록 학습할 수 있을까?
Hypothesis
  1. Context rewriting에서 보존할 정보는 task나 최종 결과와 무관하게 context 자체만으로도 결정할 수 있다.
  2. 필요한 정보를 표현하는 자연어 방식도 compression 이후 inference의 memory/latency에 영향을 미친다.

02
자연어로 compression하는 방향에서 context 자체만으로 “무엇을 보존할까?”를 결정하도록 연구 가설을 세우는 것이 타당한지
03
자연어 표현 방식이 compression 이후 inference memory/latency에 영향을 준다는 가설에 대해 어떻게 생각하시는지
