Same Concept, Different Directions (2026)

SAE는 한 입력에서 소수의 잠재 좌표만 활성화하는 오토인코더. x와 y는 각각 이미지·텍스트의 입력 임베딩. σ는 비선형 활성화 함수, z̃는 SAE 인코더와 활성화 함수를 거친 희소 활성값. 디코더에서 각 특징 방향의 활성값 가중합으로 복원 임베딩 x̃와 ỹ 생성. 입력과 복원 임베딩 사이 오차의 최소화를 위한 학습.

특징은 잠재 좌표와 그에 대응하는 방향. 모든 좌표가 반드시 하나의 해석 가능한 개념을 나타낸다는 보장은 없음. Modality split은 동일 의미의 모달리티별 활성 좌표 분리 현상.

COCO 이미지의 80개 thing 범주와 91개 stuff 범주로 구성된 총 171개 의미 범주의 픽셀 주석. 미분류 영역은 평가 범주에서 제외. Thing은 물체 종류, stuff는 배경·영역·재질을 포함한 범주. 모든 stuff가 공간적으로 뒤쪽에 위치한다는 의미는 아님.

주석 설명용 예시는 COCO validation 이미지 000000000285. 원본 COCO 2017 train은 118,287장, 이번 저장 결과의 전체 캡션은 591,753개. 물체 예시는 person, bicycle, car, train, dog, cat, bear, skis, surfboard, chair. 배경 예시는 grass, snow, sea, sand, dirt, gravel, mud, tree, clouds, floor-wood.

COCO-Stuff 주석을 활용한 Oracle 매핑의 구성

개념의 정답 주석을 알고 있다면, activation과 개념을 연결하는 세 행렬 구조를 어떻게 구성할 수 있을까?

1. 개념마다 activation k개 선택

재학습한 손실이 가장 작은 좌표를 하나씩 추가 (k=16)

S는 선택한 좌표 집합, c는 개념, j*는 이번에 추가할 좌표

2. 릿지 회귀로 A·B의 각 열 학습

이미지·텍스트 각각에서 예측 제곱오차와 가중치 크기 최소화

Z는 activation 행렬, t는 0·1 주석, w·b는 가중치·절편
N은 학습 표본 수, 1은 모든 원소가 1인 벡터, λ=0.01

3. 개념 간 대응은 항등행렬로 고정

양쪽 개념 순서를 맞춰 눈은 눈, 스키는 스키와 연결

각 열이 개념 하나를 나타내는 행렬

각 행은 원래 activation 좌표, 각 열은 개념 하나에 해당. 전체 activation 수 × 171 행렬에서 열마다 최대 k개 가중치만 사용

개념별 점수로 검색 유사도 계산

이미지와 텍스트를 각각 171개 개념 점수로 변환하고 코사인 유사도로 비교. 검색에는 평가 주석을 사용하지 않음

이미지·텍스트 모두 부모 이미지의 COCO-Stuff 주석으로 학습 · A·B는 검색 시 학습 출력 표준편차 보정을 포함한 가중치 · 입력 activation은 표준화하며 검색에서는 절편 제외
기존 Oracle 실험을 A, B, P 표기로 설명한다. 전진 그리디 좌표 선택과 릿지 재적합을 반복한다. 텍스트도 이미지 존재 주석을 사용하며 캡션 언급 주석이 아니다. A와 B는 학습 출력 표준편차 보정을 흡수한 검색용 행렬이다. 선형 점수의 코사인을 사용하고 sigmoid는 적용하지 않는다.

개념 예측 오차

지표는 평균 제곱오차(MSE)입니다. 예측값과 개념 유무의 0·1 주석 사이 차이를 제곱한 뒤, 171개 개념과 표본에 걸쳐 평균합니다. 낮을수록 주석과 가깝고, 가중치 규제 벌점은 포함하지 않습니다.

은 표본, 는 개념, 은 표본 수입니다. 는 예측값, 는 개념이 있으면 이고 없으면 인 주석입니다. 는 표본 가중치로, 이미지에서는 해당 분할에서 연결된 캡션 수이고 텍스트에서는 입니다.

학습 오차와 COCO val2017 검증 오차를 함께 비교합니다. 검증에는 학습에 사용하지 않은 이미지 5,000장과 캡션 25,014개를 사용했습니다.

Take away

  • 다대다 대응의 정렬 성능에 대한 가능성

    Soft 방식으로 개념의 의미를 직접 고려하지 않고 정렬을 최적화했을 때, 헝가리안보다 높은 검색 성능을 얻을 수 있음을 확인했음. 희소화하여 사용하는 activation이나 연결 수를 줄인 뒤에도 상당한 검색 성능을 유지했음

  • 다대다 대응의 해석 가능한 구조에 대한 가능성

    W를 A·P·Bᵀ로 나누어 activation 집합과 개념, 개념 간 대응을 구분해 표현했음. Oracle로 정렬을 직접 유도하지 않고 annotated concept을 예측하도록 학습했을 때도, 헝가리안보다 높은 검색 성능을 얻을 수 있음을 확인했음

  • 다음 질문 · 해석과 정렬을 함께 개선하는 목적함수와 제약

    두 방식의 장점을 결합해 해석 가능한 개념 대응과 정렬 성능을 함께 확보하려면 어떻게 학습해야 할까? 특히 주석 없이 activation과 개념을 연결하는 행렬을 추정하고, 양쪽 개념의 의미 대응을 유도할 수 있을까?

Soft 방식의 검색 성능은 의미 해석을 직접 최적화하지 않은 정렬 중심의 비교 기준이다. Oracle은 주석으로 의미를 지정한 비교 기준이며, 검색 또는 해석의 이론적 상한은 아니다. 개념 예측이 해당 개념에만 반응한다는 보장도 아니다. 세 행렬 구조의 의미 대응과 정렬 개선은 앞으로 함께 검증할 질문이다.
